# P0 权限与审计验收 · 2026-11-11

范围：本机 Docker Dashboard、PostgreSQL 16，以及开发、预发两个 APISIX 3.19.0 沙箱。测试用独立账号及随机命名的临时路由，不需要读取或输出真实用户密码、Admin Key 或消费者密钥。

| 验收项 | 实测证据 |
| --- | --- |
| 登录与会话 | 正确账号可登录；错误密码、被撤销的 Cookie、没有会话分别返回 401。缺少 CSRF 或来源错误的写入返回 403。账号变更后旧会话不可继续读取。 |
| 集群隔离 | 只授权开发集群的账号只能列出开发；直接访问预发的工作台、路由、插件、草稿、变更和跨环境校验引用均为 404。未授权账号的三个全局列表为空。 |
| 操作隔离 | 查看者不能写草稿；编辑者能提交待发布变更却不能发布；普通发布者不能生成、执行、取消或核对回退变更。已有接入的只读设置阻止有权限的账号新增草稿和执行发布。 |
| 真实路由 | 专用 URL 发布前 404，编辑者保存草稿后仍为 404；独立发布者发布并回读成功后为 200；回退者生成并执行回退后重新为 404。 |
| 凭据与快照 | 带唯一测试凭据的配置经创建、读取、修改、差异、发布回读、回退和审计均未回显该值。既有集成用例另外验证掩码保留原值且网关实际收到轮换后的值。Go 用例覆盖组合 Schema、本地引用、数组、映射、特殊字段名、旧快照和意外回读的插件。 |
| 审计与并发 | 实际发布、回退人分别出现在相应终态事件。集群审计者看不到系统登录和其他环境；失败登录、写入拒绝可按实际状态码筛出。游标分页不重复；过期账号授权版本返回 409。同一账号的授权修改、会话撤销与授权记录同时提交。 |
| 本地数据库抽查 | 只读 SQL 验证了账号密码字段均为 bcrypt 格式、会话标识均为 SHA-256 摘要形态、集群凭据为密文封装，并确认已有旧审计成功恢复集群归属。没有输出密码、摘要、密文或会话值。 |
| 审计存储故障 | 使用已关闭的数据库连接模拟无法登记审计的情形，管理写接口返回 503，后续修改处理器未执行。该项为隔离的服务端测试；没有让正在运行的本地数据库停机。 |

**本次结果：** 8 组权限接口联测和原有 14 组管理接口回归通过；浏览器共 48 项通过（完整运行 47 项，再单独运行新增的授权审计筛选与展开用例 1 项）；前端单元测试 54 项通过，生产构建、格式、Go 竞态与静态检查通过。浏览器确认改权后切换到缓存页面也会要求重新登录，中英文、浅深色、手机宽度和审计授权前后对照正常。

收尾时，将两个网关的路由、上游、消费者、服务和共享插件配置与已有基线逐类比对，资源数量和配置摘要一致。开发健康路由无密钥为 401、有效密钥为 200；预发回显服务返回 200。此核对不代表生产容量或所有 APISIX 3.x 版本的兼容性。

复现时先启动项目已有的开发和预发沙箱，串行运行以下命令：

```text
node scripts/test-access.mjs
npm run test:integration
npm run test:e2e
```

前端与后端另运行 `npm run typecheck`、`npm run build`、`npm run test:web`、`npm run format:check`、`go test -race ./...` 和 `go vet ./...`。测试账号与在线测试路由清理后，Dashboard 保留它们正常产生的审计历史。此次没有上线生产环境，也没有在数据面添加采集或鉴权逻辑。
