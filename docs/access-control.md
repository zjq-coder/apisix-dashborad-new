# 控制台权限与审计

登录后打开「系统设置 → 用户与权限」。建议每位操作人员使用独立账号：部署管理员建立集群连接，再按环境为成员授权。例如，开发人员可以编辑开发环境、只读查看预发环境；发布人员只在预发环境拥有发布权限。赋予发布或编辑权限之前，应按对该集群网关配置的信任程度选择人员。

| 选项 | 可以执行的操作 |
| --- | --- |
| 勾选集群 | 查看该集群的工作台、实时资源、插件、草稿、差异和发布记录；执行不落配置的校验 |
| 编辑草稿 | 创建、更新、丢弃草稿，以及将同一集群的草稿组织为待发布变更 |
| 发布变更 | 执行普通变更；核对结果或取消普通变更 |
| 回退变更 | 生成回退预览；执行、核对或取消回退变更 |
| 查看审计 | 查看该集群的审计，不能查看系统事件或其他集群的记录 |
| 管理员 | 管理连接、探测、账号、授权和全部审计；任何账号均受连接的只读设置约束 |

四项操作权限彼此独立。集群只读时仍可查看和校验；管理员可以修改连接的只读设置。编辑和发布可以交给不同账号，但没有强制双人审批。账号的集群权限不影响 APISIX 数据面消费者的认证、插件配置或转发。Dashboard 的鉴权与审计只运行在自己的管理 API 和数据库中。

**账号与会话。** 第一次升级保留集群、草稿、发布和审计记录；环境变量指定的账号成为受保护的部署管理员。调整部署密码并重新启动 Dashboard 会轮换其密码并撤销旧会话。环境管理员不能被网页禁用、删除或通过网页改密，管理员也不能在此页面修改自己的账号。修改普通账号需使用最新授权版本，旧版本会返回 409。密码以 bcrypt 哈希存储，要求 12–72 字节；会话有效期 12 小时，只保存令牌摘要。每个写请求验证 CSRF 和请求来源。按来源地址限制失败或正在进行的登录尝试；同一进程每分钟最多 8 次，成功登录不占用后续额度。生产 HTTPS 部署请启用 Secure Cookie。修改授权、停用、重置密码或删除后，该账号现有会话的下一次请求会被拒绝；已经接受的发布仍有独立执行记录。

**敏感信息。** 集群 Admin Key 仅由服务端使用；配置快照以 AES-GCM 加密。资源、草稿、差异和执行回读按内置字段规则与插件 Schema 标记脱敏，包括数组、映射、组合 Schema、本地引用与 writeOnly 字段。保留占位符会从原位置恢复值，不能用于创建一个新秘密。对不能解析的引用以及没有新版脱敏策略的旧快照，接口隐藏相应配置块。审计不写请求正文、密码、Cookie、变更说明或密钥；账号授权事件只记录允许的授权元数据。普通描述、标题和业务 ID 是可见元数据，不应填写凭据。

**审计。** 页面支持按环境、操作人、动作、结果筛选和游标翻页。记录登录、退出、账号变更和授权、连接配置、草稿、校验、发布/回退、失败或被拒绝的管理请求；成功的普通列表读取不逐条记录。HTTP 202 表示接受执行，另有 change.succeeded 等事件记录执行结果，两者均归于实际执行人。写入前先登记审计；无法登记则拒绝执行。如果 Dashboard 中途停止，已开始的事件可与变更状态核对。旧审计按现存目标恢复集群归属；没有可靠结果的保留“历史记录”，不显示旧自由文本详情，无法归属的仅管理员可见。

该机制是本地账号和 PostgreSQL 管理审计，没有接入 SSO、MFA、外部不可篡改日志或自动归档。独立于 Dashboard 直接访问 APISIX Admin API 的操作不经过本系统审计。

验收环境、实际 API 状态码和复现步骤见[权限与审计验收记录](access-verification.md)。
