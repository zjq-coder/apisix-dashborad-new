### 本地路由对照

通过同一台 Windows 主机访问测试网关的 `GET /__env/staging`。8 个并发客户端复用 HTTP 连接，每轮预热 0.8 秒、测量 5 秒。每个状态测量 4 轮，新版打开与关闭状态交错进行。每次都校验 HTTP 200 和上游标识 `echo-staging`。旧版打开时同时确认浏览器持续成功取得流量快照。

| 工作台状态 | 成功请求总数 | 吞吐（请求/秒） | P50（毫秒） | P95（毫秒） | P99（毫秒） |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧版概览打开，采集中 | 70,097 | 3,648 | 2.10 | 3.22 | 4.07 |
| 新版工作台关闭 | 92,778 | 4,198 | 1.81 | 2.83 | 3.36 |
| 新版工作台打开 | 88,712 | 4,182 | 1.84 | 2.88 | 3.54 |

吞吐和延迟列分别取四轮测量值的中位数。三组共 251,587 次请求，失败 0 次。新版开页与关页的吞吐中位数相差约 0.4%，P95 相差约 0.06 毫秒。结果反映这条本地 Docker 转发路径的短测，包含宿主机、容器网络、网关和测试上游的耗时。
