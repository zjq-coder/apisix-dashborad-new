# APISIX Dashboard Next V1.0.1

发布日期：2026 年 11 月 12 日。升级基线：V1.0.0。

本版缩短了配置从编辑到生效的流程。运维人员可以在路由列表直接上下线，在服务编辑器选择或配置上游，在集群连接页看到每个管理地址的健康状态。

## 配置发布与路由管理

- **直接发布或交给发布人。** 有编辑和发布权限的账号，可以直接保存并发布 12 类可写资源，涵盖 HTTP 与 Stream 路由、上游、服务、消费者、消费者组、独立凭据、共享插件配置、全局规则、插件元数据、Proto 和 Secret 管理器。只有编辑权限时，可直接提交待发布变更。已有草稿仍可继续编辑、提交或发布。
- **发布与回退可追溯。** 直接操作仍会生成发布记录，记录差异、执行结果和网关回读。提交时检查权限、只读状态和配置基线，生产集群需要确认名称。批量执行中途失败时，发布详情标明已应用、失败和跳过的操作，支持按记录回退已应用的配置。
- **路由列表可完成日常操作。** 每行提供发布或下线、配置、查看线上脱敏 JSON、复制和删除。工具栏提供共享插件模板、JSON 编辑、批量删除，以及 OpenAPI 的 JSON / YAML 导入导出。普通 OpenAPI 3.0 / 3.1 文件按方法和路径生成路由，默认停用。控制台导出的文件通过 `x-apisix-routes` 保存 APISIX 匹配条件、插件和上游引用。导入和批量删除每次各支持最多 50 条路由。[路由操作、导入边界与示例](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.1/docs/route-list-actions.md)

## 服务、上游与插件

- **服务可视化配置。** 支持域名、标签、WebSocket、服务级插件，以及按名称或 ID 搜索当前集群的上游。服务也可以内联节点、负载均衡、服务发现、超时、重试、连接池和主被动健康检查，或由引用它的路由提供上游。
- 服务表单校验期间会暂时禁用发布按钮，读屏工具仍可按原名称识别两个操作。校验结束后即可继续编辑并发布。
- **修复配套 APISIX 3.19.0 演示网关的节点摘除。** 新接手请求的 worker 现在会沿用已知的节点健康状态。双节点实测覆盖轮询和请求头一致性哈希，主动超时和被动 503 摘除后共发出 480 次请求，全部由健康节点返回 200；故障节点恢复后重新分担流量。修复随配套网关镜像构建，外部接入的 APISIX 需在其部署侧单独处理。[故障复现、修复范围和恢复数据](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.1/docs/operations-guide.md#双节点故障摘除与恢复实测)
- **插件配置可按字段查找。** 编辑器结合当前集群的 Schema 和随项目提供的中英文官方字段说明，支持字段搜索、必填项、可选项、类型选择、示例和复杂配置的 JSON 编辑。路由认证策略和消费者凭据按各自作用域展示，节点、Stream、SSL 或元数据类插件会提示配置位置。[插件编辑器截图与逐项验证](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.1/docs/plugin-verification.md)
- **修正插件 Schema 的空数组默认值。** 当网关把数组字段的空默认值序列化为 `{}` 时，控制台会依据该字段的数组类型还原为 `[]`，嵌套字段和条件分支也会处理。

## 集群连接

- **后台自动探测。** Dashboard 约每分钟带管理凭据读取一次 Admin API 插件列表，单次超时 5 秒。打开连接页时每 5 秒刷新已保存的结果；超过两分钟没有新结果，卡片显示「检测已过期」。卡片支持按状态筛选、搜索名称或地址，显示 APISIX 版本、最近检测时间、耗时及错误原因。手动检测可进一步验证路由和上游读取权限。所有探测均使用管理面。
- **管理员可解除接入。** 确认后停止后续探测，清除保存的管理密钥和集群授权。网关上的业务配置继续运行，历史草稿、发布及审计记录保留。正在发布的集群会拒绝删除。删除当前连接会切换到其他可用连接，最后一个连接移除后可重新接入。[集群连接页截图](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.1/docs/screenshots/cluster-connections.png)

## 从 V1.0.0 升级

使用 Git 和 Docker Compose 部署的环境，先备份 PostgreSQL，保留原来的 `.env`、`DASHBOARD_ENCRYPTION_KEY` 和数据卷。在部署目录执行：

```sh
git fetch origin tag V1.0.1
git switch --detach V1.0.1
docker compose up -d --build dashboard
docker compose ps
```

Dashboard 启动时会给已有集群记录补充探测与移除字段，并开始检测有效连接。登录「集群连接」核对状态，使用「检测连接」验证管理密钥和权限。使用配套演示环境且需要上游摘除修复时，再重建对应的网关容器：

```sh
# 开发演示网关
docker compose --profile gateway up -d --build --no-deps apisix
# 已部署的预发演示网关
docker compose -f compose.staging.yaml up -d --build --no-deps apisix-staging
```
