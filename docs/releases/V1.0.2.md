# V1.0.2 · 消费者访问范围与凭据单独授权

发布日期为 2026 年 11 月 17 日，上一版本为 V1.0.1。

同一把 API Key 以前可以通过多条启用 Key Auth 的路由。升级后，可以让它只访问订单接口，同时让同一消费者的 Basic 凭据继续按原策略访问其他接口。Dashboard 通过 Admin API 发布配置，APISIX 在识别出消费者后执行原生 `consumer-restriction`。升级本身不会给已有消费者添加白名单。[APISIX 官方插件说明](https://apisix.apache.org/zh/docs/apisix/plugins/consumer-restriction/)

## 在哪里配置

| 想实现的效果 | 操作入口 | 生效范围 |
| --- | --- | --- |
| 给一个消费者统一授权 | 「消费者管理 → 编辑 → 认证访问范围」，选择「指定路由」或「指定服务」，勾选目标并发布 | 同一消费者的内联认证和独立 Credential 共用名单。一次可选多条路由或多个服务。按服务授权包含以后绑定到该服务的路由。 |
| 只限制一种现有认证 | 在该消费者已保存的内联认证插件旁点击「单独授权」，填写新消费者用户名，选择目标并发布 | 选中的凭据迁入新身份，调用方沿用原密钥、密码或令牌。其他认证和独立 Credential 继续使用原身份。新身份继承原消费者组、标签及其他非认证策略。 |
| 从一个接口签发专用凭据 | 在已保存路由或服务的认证插件窗口点击「创建限定当前资源的凭据」 | 新标签页预选当前集群、认证方式及路由或服务，填好消费者信息和凭据即可发布。 |

目标选择器支持按名称、ID、路由路径或服务说明搜索。消费者列表显示授权目标数，可查看具体 ID。编辑器会提示找不到的目标和选中资源已有的同名策略。已有黑名单、按 HTTP 方法授权、执行条件和自定义拒绝响应可在完整插件编辑器中维护。界面支持中文、英文和窄屏布局。[消费者访问范围截图](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.2/docs/screenshots/consumer-access-scope.png) · [单独授权截图](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.2/docs/screenshots/scope-one-credential.png)

## 认证与发布行为

- **生效条件。** 集群需启用 `consumer-restriction`，目标路由或服务需配置能够绑定消费者身份的认证。公开路由继续按自身配置处理。消费者和路由、服务或消费者组同时配置同名插件时，消费者配置优先生效。
- **支持单独授权的认证。** 已验证 `key-auth`、`basic-auth`、`jwt-auth`、`hmac-auth`、`ldap-auth`、`ldap-auth-advanced` 和 `wolf-rbac`。LDAP Advanced 需开启 `consumer_required`。JWE 解密本身不绑定消费者，要限制接口访问，可与 Key Auth 等身份认证组合使用。
- **凭据迁移。** 同一条发布记录先解除原身份的内联绑定，再创建带白名单的新身份。两次写入之间可能短暂返回 401。上游收到的 `X-Consumer-Username` 会变为新用户名，按用户名配置的 ACL、配额或上游授权需要一并核对。
- **权限、审计与回退。** 编辑员可提交待发布变更，具备编辑和发布权限的账号可直接发布。服务端检查配置基线、目标 ID 和新用户名，发布详情中的凭据脱敏。操作审计支持按 `consumer.scope-credential` 筛选。多项变更按实际写入的逆序回退，完整迁移会先删除新身份、再恢复原绑定。若第二项写入失败，可在发布详情中选择「回退已应用配置」。
- **管理接口。** 新增 `POST /api/v1/clusters/{id}/consumers/{username}/scope-credential/{mode}`，支持 `submit` 与 `apply`。插件目录返回 `can_scope_credential`，供客户端判断当前插件是否支持单独授权。[接口参数及发布流程](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.2/docs/api.md#直接提交和发布)

## 从 V1.0.1 升级

使用 Git 和 Docker Compose 部署时，保留原项目目录、`.env`、数据库卷和 `DASHBOARD_ENCRYPTION_KEY`。已有 PostgreSQL 正常运行时，只需重建 Dashboard。本版没有新增数据库迁移。

```sh
git fetch origin tag V1.0.2
git switch --detach V1.0.2
docker compose up -d --no-deps --build dashboard
docker compose ps dashboard
```

访问 `/healthz` 确认控制台可用。首次启用白名单时，用同一份有效凭据各请求一个允许和一个未列入的认证接口，即可核对实际边界。[全新部署与多环境接入](https://github.com/zjq-coder/apisix-dashborad-new/blob/V1.0.2/README.md#部署方式)
